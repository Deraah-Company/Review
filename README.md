# أكاديمية درعة — نسخة العرض الكاملة

آخر ملفات المشروع مع نسخة مستقلة من أمثلة الأكاديمية بتاريخ 21 أكتوبر 2026. هذه نسخة جاهزة للرفع كمستودع GitHub وتشغيلها باستخدام Docker. لا يلزم استيراد قاعدة البيانات يدويًا: تُنسخ الأمثلة تلقائيًا عند أول تشغيل فقط، وتُحفظ التغييرات اللاحقة في مجلد/قرص البيانات المستخدم.

## التشغيل السريع على الكمبيوتر

1. شغّل Docker Desktop.
2. فك ضغط الحزمة، ثم افتح ملف Start-Demo.cmd، أو افتح Terminal داخل المجلد ونفّذ:

    docker compose up -d --build

3. افتح http://localhost:3001

اسم حاوية المشروع ووحدة التخزين مختلفان عن النسخة الأصلية، والمنفذ 3001؛ لذلك يمكن تشغيل هذه النسخة بجانب الموقع الأصلي على المنفذ 3000. لا يحتاج Docker إلى ملف .env في هذه الحزمة.

## حسابات العرض

كلمة المرور لجميع حسابات نسخة العرض: **Demo!Academy2026**

| الدور | البريد |
|---|---|
| مدير الأكاديمية | admin@academy.local |
| مدرب لديه صلاحية إضافة دورة | sidebar.qa@academy.local |
| مدرب بصلاحيات مشاهدة محدودة | trainer2@academy.local |
| متدرب لديه تقدم وشهادات | followup.qa@academy.local |
| متدربة أخرى | learner2@academy.local |
| متدرب مراجعة الأسئلة والدعم | review.demo@academy.local |

تغيير كلمات المرور تم في نسخة العرض فقط. النسخة الأصلية وجميع بياناتها ظلت كما هي. أُزيلت جلسات تسجيل الدخول القديمة وحالة الاتصال من نسخة العرض. حالات الحسابات وصلاحياتها محفوظة كما هي؛ فالحساب learner@academy.local موقوف في البيانات الأصلية، ولذلك استخدم حسابات العرض الفعالة الموضحة أعلاه. لا تستخدم بيانات الدخول التجريبية لموقع إنتاجي.

## الأمثلة المرفقة

32 دورة، و42 عنصر محتوى، و6 مسارات، و13 حسابًا تجريبيًا، و6 شهادات صادرة، و3 قوالب شهادات، و5 امتحانات مجدولة بمحاولاتها، ومكتبتا استبيانات و12 مشاركة، و4 أسئلة متدربين، و7 رسائل محادثة، و4 تذاكر دعم، وأمثلة النقاط والكوبونات والإعلانات والجلسات التدريبية والقاعات وتقارير الشراء. لم تُحذف أمثلة الاختبار والنتائج عند تجهيز الحزمة. توجد الفيديوهات والصور والملفات المرفوعة داخل demo-data/uploads، وقاعدة أمثلة العرض داخل demo-data/academy.sqlite.

تواريخ الامتحانات والنتائج محفوظة كما هي؛ قد تكون الامتحانات السابقة مغلقة الآن، وتظل نتائجها في إدارة الامتحانات. لإظهار امتحان جديد نشط يمكن إنشاء نسخة جديدة منه بموعد مناسب. الدفع محاكاة تجريبية، وليس تحصيلًا ماليًا حقيقيًا.

## رفع المشروع إلى GitHub

لا ترفع ملف ZIP نفسه على أنه موقع، ولا ترفع public/index.html وحده. فك الحزمة وارفع محتويات مجلد المشروع. استخدام GitHub Desktop مناسب لأن هناك فيديو بحجم يقارب 48 ميجابايت، وهو أكبر من حد رفع الملف الواحد من متصفح GitHub (25 ميبيبايت). لا يوجد ملف في الحزمة يتجاوز 100 ميبيبايت.

1. افتح GitHub Desktop وسجّل الدخول.
2. اختر File ثم New repository. سمّه deraah-academy-demo واختر مكان حفظه.
3. انسخ كل محتويات هذه الحزمة إلى مجلد المستودع الذي أنشأته، بحيث يظهر Dockerfile وcompose.yaml وREADME.md مباشرة في جذر المستودع.
4. من Changes اكتب وصفًا مثل Latest academy demo with examples ثم اضغط Commit to main.
5. اضغط Publish repository واترك Keep this code private محددًا، ثم Publish Repository.

ملف .gitignore يستبعد البيانات التي تتغير أثناء التشغيل وملف .env، لكنه يضم demo-data لأن هذا هو مصدر أمثلة العرض. مجلد original القديم والنسخ الاحتياطية القديمة وبيانات الجلسات الأصلية ليست ضمن الحزمة. لم يتم رفع أي شيء إلى حساب GitHub تلقائيًا.

## الحصول على رابط تعرضه على شخص آخر

GitHub Pages لا يشغّل هذا المشروع كاملًا لأنه يحتاج إلى سيرفر Node.js وقاعدة SQLite؛ عرض HTML ثابت وحده لن يُظهر النظام والبيانات.

مرفق ملف render.yaml لتشغيل نسخة عرض مجانية على Render بدون قرص دائم:

1. بعد رفع المستودع، افتح https://dashboard.render.com/ وسجّل الدخول، ثم اربط مستودع GitHub.
2. اختر New ثم Blueprint وحدد المستودع. سيقرأ Render ملف render.yaml من جذر المشروع.
3. راجع إعدادات الخدمة: Docker والخطة Free، ثم أنشئ الخدمة.
4. بعد نجاح النشر افتح رابط الخدمة وأرسل الرابط مع حساب المتدرب لمن تريد عرض النسخة عليه. حساب الأدمن متاح إذا أردت استعراض الإدارة أيضًا.

**حفظ البيانات على الاستضافة المجانية:** جميع الأمثلة الحالية مدمجة في المستودع وتعود تلقائيًا عند إنشاء مثيل جديد. التغييرات الجديدة التي يجريها الزائر، مثل حسابات أو ملفات أو نتائج جديدة، قد تُفقد عند إعادة التشغيل أو النشر على خدمة بلا قرص دائم. للاحتفاظ بهذه التغييرات، استخدم خدمة بقرص دائم وركّبه على /app/data؛ الأقراص الدائمة في Render تتطلب خدمة مدفوعة. لا يُستخدم قرص مدفوع في ملف render.yaml المرفق.

## مكان ملف HTML

الواجهة داخل public/index.html، وباقي الواجهة داخل public/app.js وملفات CSS والوحدات والمكتبات المجاورة. تنفيذ الدخول والصلاحيات والبيانات والرفع والتقارير يحتاج إلى ملفات السيرفر الموجودة بجانب Dockerfile.
